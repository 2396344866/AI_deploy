## TB6612FNG 到位：接线 + 测试方案
- 已给出完整接线方案（STM32↔TB6612 信号、TB6612↔电机动力+编码器、VM/VCC/GND 电源分配），见对话与 Doc/Pinout.md 第7节。
- **关键修正（硬伤）**：Pinout.md 原写 `VCC 接 5V` 是错的——已改为 **VCC 接 3.3V**（与 H7 IO 同电平）。
  原因：TB6612 Vih=0.7×VCC，VCC=5V 时门槛 3.5V > H7 GPIO 高 ~3.3V，方向/PWM 识别不可靠。
- 接线顺序：先 GND+VCC+STBY → 上电验证 → 加 6 路信号 → 最后上 VM(6~12V,限流1A/路)+电机+编码器。
- 测试分 5 阶段（非破坏优先）：不通电通断检查 → 仅逻辑电(Motor inited, STBY=3.3V) → 逻辑分析仪抓 10kHz PWM → 单电机点动(固定占空比验证硬件) → 编码器手转验证 → 闭环 PID 整定。
- 提醒：编码器若开漏需上拉（CubeMX PB4-7 设 Pull-up 或外部 4.7k→3.3V）；ENCODER_PPR=11 为估算待实物校准。

## 串口命令接口已实施（方案A，让电机无表验证能转）

- 根因澄清：run=1 只解除刹车，target_speed 默认 0 → 电机不转属预期，非故障。

## 排查：发 A50 无反应（串口 RX 链路）
- 固件链路已逐项核对均正确：main.c:123 `BSP_UART1_RxStart()`；stm32h7xx_it.c USART1_IRQHandler 调 `BSP_UART1_IdleHandler()`；IdleHandler 调 `BSP_UART1_OnFrame`；freertos.c 重定义 OnFrame→`Motor_ProcessCommand`。
- **NVIC 已使能**（usart.c:250-251 `HAL_NVIC_EnableIRQ(USART1_IRQn)`），排除中断未开。
- 结论：代码侧无问题，零反应最可能是 **硬件 RX 接线缺失**——日志能出说明 PA9(TX)→适配器RX 通；PC→MCU 需 适配器TX→PA10(RX)，那根线很可能没接。
- 已加**原样回显**到 OnFrame（freertos.c USER CODE）：发 `A50` 若终端回显 `A50`=RX通→电机应转；若毫无回显=RX 线没接。校验 EXIT=0。
- 接线提醒：USB-TTL 必须交叉——适配器TX→PA10、适配器RX→PA9、GND 共地；只接 TX 一侧则只能看日志不能收命令。

## 根因实锤：发 A50 回显 `\0\0\0\0`（H7 D-Cache 一致性）
- 收到回显 4 字节全 0 → 推翻"PA10 未接"假设：IDLE 触发、收到 4 字节、能回显 = RX 帧链路通；但数据全 0 = CPU 读到的全是 0。
- **真因**：main.c:89 `SCB_EnableDCache()` 开着 D-Cache；`s_uart1_rx` 在可缓存 RAM，DMA 把串口字节写入 RAM，但 CPU 从 D-Cache 读到 BSS 旧值(0)。TX(fputc,CPU 自写)正常，故日志能看、收命令是 0。这是 H7 DMA+Cache 经典坑。
- **修复**：`BSP_UART1_IdleHandler` 在读缓冲前调 `SCB_InvalidateDCache_by_Addr()`（地址 32 对齐、长度向上取整 32）失效对应 Cache 行，强制从 RAM 取真实数据。改动仅在 BSP_USART.c（组件内，非 CubeMX 生成）。
- 校验：BSP_USART.c 用 ARM GCC `-fsyntax-only` EXIT=0。
- 后续：重烧后发 A50 应回显 A50 + 打 `A target=50` + 电机A转。诊断回显（freertos.c OnFrame 里 HAL_UART_Transmit 回显）确认 RX 后可去掉。

## 根因实锤（2）：回显 A50 但仍无日志/电机不转 = 中断里做重活挂死
- 现象：D-Cache 修复后发 A50 回显正确，但无 `A target=50` 日志、电机不动、遥测停更。
- **真因**：`BSP_UART1_OnFrame` 在 USART1 中断上下文被调用，原实现在里面 (1) `HAL_UART_Transmit` 阻塞回显（复用正在 DMA 收发的 huart1 句柄）+ (2) 直接调 `Motor_ProcessCommand`→`LOG_I`/`Motor_Resume` 改电机状态。这两者在 ISR 中执行会与 huart1/DMA 冲突导致系统挂死；回显是 ISR 内直接发的所以出现，其后所有处理全部丢失 → running 一直 0 → 电机刹车不转。
- **修复（正确嵌入式架构：ISR 只收帧+发信号，处理推迟到任务）**：
  - freertos.c 新增 `s_cmd_rx[32]`/`s_cmd_rx_len`/`s_cmdSemHandle`（声明移到 `USER CODE BEGIN Variables`，因 Application 块在任务函数之后）。
  - `BSP_UART1_OnFrame`(ISR) 仅拷贝帧 + `osSemaphoreRelease(s_cmdSemHandle)`（CMSIS-RTOS2 ISR 安全），**不 LOG/不阻塞发送/不改状态**。
  - `StartMotorTask` 启动前 `osSemaphoreNew(1,0,NULL)`；循环内 `osSemaphoreAcquire(...,0)` 取到帧后在**任务上下文**回显 + 调 `Motor_ProcessCommand`（可安全 LOG/改状态，running 置 1 → TIM7 控制环输出 PWM → 电机转）。
- 校验：freertos.c ARM GCC `-fsyntax-only` EXIT=0。
- **通用经验（记入 Skill 候选）**：STM32H7 上 UART-DMA+IDLE 的 OnFrame 绝不能做任何阻塞/RTOS/状态变更，必须 defer 到任务（信号量/队列）。同项目已踩两坑：D-Cache 一致性 + ISR 内重活挂死。
