### 1.1 轴系对齐 R_mag ✅（2026-08-25）

- 实现：安装欧拉角 `MAG_INSTALL_YAW/PITCH/ROLL_DEG`（默认 0）按 ZYX 生成对齐矩阵，磁力计 raw 先旋到 IMU body 系再减硬铁偏移。

### 1.2 倾角补偿罗盘 ✅（2026-08-25）
- 文件：`attitude.c` `Attitude_TiltCompassHeading()`（CH34 已改用此值，替代原水平 atan2）
- 公式（已落代码）：
  ```
  mx2 = mx_c*cos(pitch) + mz_c*sin(pitch)
  my2 = mx_c*sin(roll)*sin(pitch) + my_c*cos(roll) - mz_c*sin(roll)*cos(pitch)
  heading = atan2(-my2, mx2)
  ```
  其中 mx_c/my_c/mz_c = 轴系对齐后 calib；pitch/roll 取自融合角（s_att_raw，无后滤波延迟）。
- VOFA：CH29(6轴yaw, 漂移) vs CH34(磁航向, 稳定) 对比图即目标产出。

## 3. ESP32-S3 CAM 图像结论接入 ✅（2026-08-26 解析落地）

**目标**：H743 只收 ESP32-S3 的"图像结论帧"，零 DCMI/零图像算力（Pinout §12 已定稿方案 B）。

### 3.1 接收端实现（STM32 侧）
- 文件：`Components/BSP/ESP32S3/Inc/esp32s3.h` + `Src/esp32s3.c`（自建模块，CubeMX 重生成不覆盖；Keil 需把该 .c 加入工程树 + `Components/BSP/ESP32S3/Inc` 加入 Include Paths）。
- 接口：`ESP32S3_BSP_Init()`（在 `freertos.c` `MX_FREERTOS_Init` 的 `USER CODE BEGIN Init` 调用，建队列+任务+强制波特率）、`ESP32S3_GetLatest()`（其它任务读最新一帧快照）、`Queue_ImgResultHandle`（公开队列句柄）。
- 链路：USART6(PC6/7) 921600（设计值 Pinout §3.8）；引脚/IRQ/NVIC 已由 CubeMX 生成，**你只需物理连线**。

### 3.2 接收机制（关键决策）
- **不用 DMA**：`.ioc` 未配 USART6 的 DMA2，改用 `HAL_UARTEx_ReceiveToIdle_IT`（纯中断 + IDLE 切帧），小帧率 FOMO 结果绰绰有余，且免去你配 DMA 的麻烦。
- **ISR 极简**（遵循 error.md E2 铁律）：`HAL_UARTEx_RxEventCallback` 里只做"字节喂状态机 + 完整帧入队(`osMessageQueuePut`，ISR 安全) + 置任务标志"，**绝不调用 LOG_I / 阻塞发送**。
- **帧解析状态机**：找帧头 `AA 55` → 读 L → 读 CMD → 收载荷 → 收 CRC16 → 校验 → 发 `CMD=0x01` 检测帧到 `Queue_ImgResultHandle`。CRC 用 CRC-16/MODBUS（poly 0x8005/反射 0xA001，init 0xFFFF），计算区间 = CMD+载荷（详见 Pinout §12.6）。
- **调试统一经 UART1**：解析任务(`Task_Esp32`)是唯一队列消费者，取出后写 `s_latest` 快照并打 `LOG_I("ESP32", ...)`；受 `dbg_config.h` 的 `DBG_LOG_ESP32` 开关控制（默认 0）。串口发 `X` 命令打印接收统计（帧数/CRC 错/丢帧）到 PC。

### 3.3 ESP32 侧（另一工程，你实现固件）
- 按 §12.6 帧格式上报：FOMO 网格质心 → 归一化中心 `cx_norm=(cell_x+0.5)/GRID_W` ×1000 取整 → `CMD=0x01` 帧。
- **CRC16 必须与本端完全一致**（CRC-16/MODBUS），否则 H743 侧 `s_crc_err` 计数涨、帧被丢弃。
- H743 收端已就绪，烧录后双方串口对通即可在 VOFA/串口助手看 `DET n=..` 日志。

- 仍停在 `entering [1/1] Logger` 之后、**仍无 `*** HARD FAULT ***` 横幅**。
- **代码级结论（非硬 fault）**：P3b `HardFault_Handler`(stm32h7xx_it.c:106) 的第一动作是轮询 `log_backend_putc` 打横幅（用与 "entering" 同一 uart 链路——`entering` 刚成功打印，证明该链路此刻可用）。CM7 上任何 fault 必升级到 HardFault → 横幅必现。横幅缺失 ⇒ **没进 HardFault_Handler ⇒ 不是 HardFault，而是无限循环/阻塞自旋**。
- **MDK 暂停 PC 给出真相**：`prvTaskExitError`(`port.c:235`) —— FreeRTOS 的任务函数 return 安全网。
  - **API 作用**：任务函数不允许 return（没有返回地址），若 C 函数体执行到 `}`，FreeRTOS 会跳转到这里先 `configASSERT` 检查是否在临界区，然后 `portDISABLE_INTERRUPTS()` + `while(1)` 冻结，提示应用层任务未正确结束。
  - **本工程根因**：LOGGER profile 下只有 `APP_ENABLE_LOGGER=1`，但 `MX_FREERTOS_Init`(freertos.c:303–328) **未对 osThreadNew 做 APP_ENABLE_X 门控**，仍然创建了 Inference/Motor/Network/Sensor/Screen/Flash/Esp32S3 任务。这些任务的函数体被 `#if APP_ENABLE_X` 裁空后直接 `return` → 7 个任务几乎同时触发 `prvTaskExitError`。该函数一旦进入就全局关中断，所以串口后续输出（包括 `[1/1] Logger ...`、`Self-Test done` 等）全部被打断，看起来像是 POST 卡死。
- **修复（已落地）**：在 `freertos.c` 的 7 个被 APP_ENABLE_X 门控的任务函数末尾（`#endif` 后）统一加 `osThreadTerminate(osThreadGetId());`：
  - `StartInferenceTask`/`StartMotorTask`/`StartNetworkTask`/`StartSensorTask`/`StartScreenTask`/`StartFlashTask`/`StartEsp32S3Task`
  - 模块使能时，函数体内部已有 `for(;;)`，永远不会执行到 `osThreadTerminate(osThreadGetId())`；模块禁用时，空函数体之后自删，避免 return 触发 `prvTaskExitError`。
- **验证**：Rebuild All → Download（`APP_ENABLE_WATCHDOG=0`）→ 串口应继续输出 `[1/1] Logger ...` → `Logger_Test` 各级别 smoke → `Logger OK` → `=== Self-Test done ===` → `Task_Test stack: ...`，随后 `Task_Test` 通过 `osThreadTerminate(osThreadGetId())` 自删（CMSIS 层 NULL 非"自身"哨兵，必须用有效句柄，否则 NO-OP 落 `prvTaskExitError`）。之后系统应只剩 `Task_logger` 循环 drain + 控制台存活。
- **更长远的 CubeMX 边界**：这 7 处 `osThreadTerminate(osThreadGetId())` 位于各任务函数的 `USER CODE` 块内，CubeMX 重生成会保留，不会漂移；比直接改 `MX_FREERTOS_Init` 的生成区更安全。

### 7.7 已解决确认（22:16 串口，PASS）
