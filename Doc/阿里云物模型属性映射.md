# 阿里云物模型：Topic 与属性映射

> 目标：让 STM32 既能**上报**属性，也能**接收云端下发控制**（APP/小程序 → 设备）。
> 约束：**复用 IoT 控制台已发布的标识符，不新建物模型**（改物模型会影响已发布版本，且批量新建成本高）。

---

## 1. Topic 结论速查

| 方向 | Topic | 角色 | 是否实现 |
|---|---|---|---|
| 上行 | `/sys/{pk}/{dn}/thing/event/property/post` | **发布**（物模型 10 属性，5s 周期） | ✅ |
| 上行 | `/sys/{pk}/{dn}/thing/service/property/set_reply` | **发布**（下发处理结果回执） | ✅ |
| 上行 | `/{pk}/{dn}/user/infer` | **发布**（推理指标 + 姿态，自定义，不进物模型） | ✅ |
| 下行 | `/sys/{pk}/{dn}/thing/service/property/set` | **订阅**（云端下发控制入口） | ✅ |
| 下行 | `/sys/{pk}/{dn}/thing/event/property/post_reply` | 订阅（云端对上报的响应） | ⬜ 可选 |
| 自定义 | `/{pk}/{dn}/user/get` | 订阅（字符串透传） | ⬜ 暂不需要 |

### 关于 `writeIotTopic`

| 调用 | 说明 | 结论 |
|---|---|---|
| `writeIotTopic(1005, ".../STM32_dev/thing/service/property/set", data)` | APP → STM32 下发属性 | ✅ **正是需要的下行入口**，STM32 订阅后即可收 |
| `writeIotTopic(1004, ".../APP_dev/thing/service/property/set", data)` | STM32 向 APP_dev 发"属性设置" | ❌ **方向反了**：STM32 上报应走 `property/post`，APP 端订阅该 topic 收数据 |

> 即：只需 APP 端调 **1005**，STM32 侧实现订阅即可闭环；1004 不需要。

### 关于自定义 `user/get`

旧版 AT 代码里的 `AT+MQTTSUB=0,"/%s/%s/user/get",1` 属于**自定义 topic 通信**。当前物模型 `property/set` 已能覆盖"下发开关/目标值"需求，`user/get` 作为二次扩展项（需要额外写 SUBSCRIBE + 解析，代码已具备复用能力）。

### ⚠️ 复数 vs 单数

旧配置 `thing/event/propertie**s**/post` **不是**标准物模型 topic。控制台「物模型通信 Topic 列表」给出的是单数 `thing/event/propert**y**/post`。已在 `esp01s_config_local.h` 修正。

## 2. 下行链路实现

```
ESP01S_MQTT_Connect()         CONNACK
   ↓
ESP01S_MQTT_Sub(SUB_TOPIC)    SUBSCRIBE → SUBACK
   ↓
[每 200ms]  ESP01S_MQTT_PollPublish()   ← 解析透传下行 PUBLISH(QoS0)
   ↓
topic 含 "property/set" ?
   ↓ 是
ESP01S_AliIot_HandleSet(payload, reply)  → 逐个属性调 setter → 组装 set_reply
   ↓
ESP01S_MQTT_Pub(SET_REPLY_TOPIC, reply)
```

> 全部能力封装在 **ESP01S 模块**（`Components/BSP/ESP/{Inc,Src}/esp01s.{h,c}`），无独立组件文件，Keil 工程无需新增源文件。

关键实现点（`Components/BSP/ESP/Src/esp01s.c`）：

- `ESP01S_RX_BUF_SIZE` 由 320 → **512**，容纳完整 set 帧（150~300 B）；
- `ESP01S_MQTT_PollPublish()` 用 `ring_at()` **原地解析** varint + topic，不 peeking 到栈缓冲（Task_Network 栈仅 2048 B）；
- **非 PUBLISH 包（PINGRESP/SUBACK 等）自动计算长度并消费**，避免 ring 头部卡死在无法识别的字节；
- 数据不足时返回 `ESP01S_ERR_NORESP` 等下一轮，**不丢半包**。

## 3. 属性映射表（10 个，全部复用已有标识符）

| # | 标识符 | 物模型名称 | 类型 | 读写 | 映射到 AI_deploy |
|---:|---|---|---|---|---|
| 1 | `LED_1` | LED开关 | bool | **读写** | `LED_R()` 板载红灯（状态镜像在 `s_prop_led`） |
| 2 | `balance_enable`(v4b) / `Euler_angle_open`(旧) | 平衡使能**意图** | bool | **读写** | 自治关：`Attitude_SetEnable()` 直控；自治开：置站起/坐下意图交 FSM 仲裁（见 balance_autonomy_plan.md） |
| 3 | `Euler_angle_Pitch` | 欧拉角俯仰角 | float | 只读 | `Attitude_GetPitch()` |
| 4 | `Euler_angle_Roll` | 欧拉角横滚角 | float | 只读 | `Attitude_GetRoll()` |
| 5 | `Euler_angle_Yaw` | 欧拉角偏航角 | float | 只读 | `Attitude_GetYaw()`（无磁力计修正时会漂） |
| 6 | `move_stop` | 机器人停止 | bool | **读写** | `Motor_EmergencyStop()` / `Motor_Resume()` |
| 7 | `move_on` | 机器人前进 | bool | **读写** | 双轮前进 |
| 8 | `move_back` | 机器人后退 | bool | **读写** | 双轮后退 |
| 9 | `move_left_rotate` | 机器人左旋转 | bool | **读写** | 原地左转 |
| 10 | `move_right_rotate` | 机器人右旋转 | bool | **读写** | 原地右转 |
| 11 | `temp` | 温度 | float | 只读 | **MPU6050 芯片温度**（非环境温度，见 §5） |

> 共 11 项（含 `temp`）；其中 **5 个可下发控制**（LED / 欧拉角开关 / 停 / 前进 / 后退 / 左转 / 右转 = 7 个可写）。

> **v4b 自治语义更正**：标识符 `Euler_angle_open` 在自治启用后将更名为 `balance_enable`，语义从“直接开关平衡”改为“**站起/坐下意图**”——本地 FSM 才是平衡使能的唯一决策者，云端/KEY 不再直控电机。角度上报（Pitch/Roll/Yaw）**永远开启**，与平衡开关解耦。详见 `Components/Motor/balance_autonomy_plan.md`。

### 3.1 电机方向（实测中心对称，勿凭直觉改）

`motor_debug.md:10` 实测结论：**A50 = 左轮前进，B50 = 右轮后退**（两电机中心对称安装）。

| 物理动作 | 左轮 | 右轮 | 命令 |
|---|---|---|---|
| 前进 | 前进 A(+S) | 前进 B(**−S**) | `A=+S, B=−S` |
| 后退 | 后退 A(−S) | 后退 B(**+S**) | `A=−S, B=+S` |
| 原地左转 | 后退 A(−S) | 前进 B(**−S**) | `A=−S, B=−S` |
| 原地右转 | 前进 A(+S) | 后退 B(**+S**) | `A=+S, B=+S` |

`ESP01S_ALIIOT_MOTION_SPEED`（默认 **120** 计数/节拍）在 `esp01s.h` 可调。
物模型 `move_*` 是 **bool**，只能表达"做/不做"，速度取固定值。改硬件装反只需调 `motor.c` 的 `cmd_dir`，**不要动这张表**。

### 3.2 互斥与安全

- `move_*` 之间互斥：置位任一动作会覆盖 `s_prop_move`，下发 `0` 归零；
- `move_stop=1` → 刹车 + `running=0`，此后所有运动指令**不偷偷转轮**；
- 下发任一 `move_*=1` 会**自动解除刹车**（无需先发 `move_stop=0`）；
- `ESP01S_AliIot_Init()` 上电置安全态：LED 灭、电机停机。

## 4. 报文格式

### 4.1 下行（云端 → 设备）

```json
{"method":"thing.service.property.set","id":"12345","params":{"LED_1":1},"version":"1.0.0"}
```

解析用 `prop_json_get()`（顶层 key 精确匹配，不建树，不引入 cJSON）：
- 取 `id` 回带到 reply；
- 遍历属性表，命中**且 writable** 的调 setter；
- bool 值兼容 `0/1` 与 `true/false`。

### 4.2 回执（设备 → 云端）

```json
{"id":"12345","code":200,"data":{}}
```

### 4.3 上行（设备 → 云端，物模型）

```json
{"id":"7","version":"1.0","params":{
  "LED_1":0,"balance_enable":1,
  "Euler_angle_Pitch":-3.62,"Euler_angle_Roll":0.15,"Euler_angle_Yaw":45.30,
  "move_stop":1,"move_on":0,"move_back":0,"move_left_rotate":0,"move_right_rotate":0,
  "temp":33.51
},"method":"thing.event.property.post"}
```

### 4.4 上行（自定义 `user/infer`，不进物模型）

```json
{"infer":{"acc":0.9090,"prec":0.91,"rec":0.90,"f1":0.90,"ms":1605.0},
 "att":{"roll":0.15,"pitch":-3.62,"yaw":45.30,"mag_h":128.4}}
```

> 推理指标（acc/prec/rec/f1/ms）在物模型里**没有对应标识符**，硬塞进 `params` 会被物模型解析器拒绝，故单独走自定义 topic，云端用规则引擎/AMQP 消费。

## 5. 刻意不映射的属性（无实体传感器）

| 标识符 | 原因 |
|---|---|
| `ultrasound_distance` / `smoke_density` / `LightLux` / `hum` / `Pressure` / `Water_Flow` / `steering_angle` | AI_deploy **无对应硬件**。伪造数据会污染云端曲线、误导告警，宁缺毋滥。 |
| `temp` 的语义 | 映射的是 **MPU6050 芯片温度**（`raw/340 + 36.53`），**不是环境温度**。芯片自热会使其高于环境数 ℃，仅作趋势参考。 |
| 其余 `move_left` / `move_right` | 差分转向（一边慢一边快）与 `move_*_rotate`（原地旋转）语义重复，优先用 rotate；需要差速时再扩。 |
