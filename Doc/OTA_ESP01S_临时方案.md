# OTA 临时方案（ESP-01S 现有模组）— 与 ESP-12F 最优解衔接

> 适用：当前手头**仅有 ESP-01S**，ESP-12F 交期约半天。本文为 **ESP-01S 临时过渡方案**，核心 OTA 逻辑完全复用 `Doc/OTA.md`（ESP-12F 最优解），仅模组层差异在此说明。
>
> **铁律（与 OTA.md 一致）**：ESP 仅作 Wi-Fi/MQTT **AT 透传物理通道**；固件 OTA 全链路（校验 / 双 Bank / 回滚）由 **H743 独立闭环**。无论 01S 还是 12F，H743 侧代码与状态机**一字不改**。
>
> 关系定位：`Doc/OTA.md` 当前正文仍以 ESP-01S 撰写，但其架构（H743 闭环 + ESP 仅透传）对 01S/12F 完全通用；ESP-12F 到货后，按本文 §5 把 OTA.md 的模组描述从 01S 对齐为 12F，即得到最优解文档。本文是 12F 到货**前**的 ESP-01S 临时执行版。

---

## 0. 与最优解的关系（一张表看清）

| 维度 | ESP-01S（本文·现有/临时） | ESP-12F（OTA.md·最优解/待到货） | 对 OTA 链路的影响 |
|---|---|---|---|
| 主控芯片 | 同为 **ESP8266EX** | 同为 ESP8266EX | **无**——AT/MQTT 指令集相同 |
| 模组 Flash | 1 MB | 4 MB | **无**——OTA 包存 H743 内部 Flash，ESP Flash 不存固件 |
| 可用 GPIO | 运行期仅 TX/RX/CH_PD（GPIO0/2 仅烧录strap） | 多余 GPIO 可扩复位/状态指示 | 仅**状态指示来源**不同，见 §3 |
| 射频 | 板载天线，抗扰一般 | PCB 天线，工业更稳 | 仅**现场覆盖余量**不同，见 §4 |
| AT 固件 | 需刷**带 MQTT** 的 AT 固件 | 同 | 同一份烧录流程（易错 1） |
| 定位 | 原型验证 / 实验室 | 量产工业选型 | 01S 先跑通，12F 到货即换 |

**结论**：两份文档**共享同一套 H743 OTA 状态机 / 校验 / 回滚**（OTA.md §4 / §5）。差异只在「模组接线 + 状态指示来源 + 射频余量」三层，均不改变 OTA 逻辑。

---

## 1. 为什么 ESP-01S 现在就能跑通 OTA

- 复用 OTA.md §1：你已完整对接过 ESP-01S 的阿里云 MQTT。ESP-01S 出厂默认 AT 固件不支持 MQTT，但你**已刷过带 MQTT 的 AT 固件**（易错 1：用 `AT+MQTTUSERCFG?` 验证有响应）。
- OTA.md §5.3 的「下载 + 边下边烧」全在 H743 的 **APP 工程内**跑，经 **USART2(PA2/PA3)** 与 ESP 交互；ESP 只转发字节。换模组不换这一层。
- 因此：**现在用 ESP-01S 即可完整验证 OTA 全链路**（含双 Bank 边下边烧、CRC、回滚、看门狗）。12F 到货后只是换一颗模组，H743 固件二进制可原样复用。

## 2. ESP-01S 接线（USART2，与 OTA.md §5.7 一致）

| ESP-01S 引脚 | STM32 | 说明 |
|---|---|---|
| **TX** | **PA3 (USART2_RX)** | 交叉接 |
| **RX** | **PA2 (USART2_TX)** | 交叉接 |
| **CH_PD (EN)** | 3.3V（或 H743 一个 GPIO 做使能，建议常高） | 必须拉高模组才工作 |
| **VCC** | 3.3V（**独立 LDO**，峰值 ~300 mA） | 单板 LDO 电流要够，勿与 MCU 共一路弱源 |
| **GND** | GND | 共地 |
| GPIO0 / GPIO2 | 烧录 AT 固件时拉低/拉高，**运行态悬空** | 仅 boot-strap 用，运行期不可作通用 IO |
| RST | 可选（H743 GPIO 或上拉） | 远程硬复位 ESP 才需要 |

- 波特率 **115200**（OTA.md §2 / §5.7，`esp01s.c` 已确认；中断接收 `HAL_UARTEx_ReceiveToIdle_IT`，无需 DMA）。
- ⚠️ **不要与 ESP32-S3 共用 USART2**（待处理.md §2 / Pinout §0 铁律）。
- 调试顺序：先用串口助手单独给 ESP-01S 发 `AT` / `AT+GMR` / `AT+MQTTUSERCFG?` 确认固件与 MQTT 可用，再接 STM32 USART2。

---

## 3. 状态指示差异（01S 无多余 GPIO 可暴露）

- **12F 最优解**：可用 ESP 多余 GPIO 做「复位 / 状态指示」。
- **01S 临时方案**：ESP 运行期无多余 GPIO 可暴露，状态指示**改由 H743 自身承担**：
  - OTA 进度 / 状态走 **MQTT 上报**（OTA.md §5.3 `mqtt_report_progress`），不依赖 ESP GPIO。
  - 本地状态灯用 **H743 一个空闲 GPIO**（如某 LED）或 **USART1 VOFA 遥测**显示。
  - 如需远程硬复位 ESP，由 **H743 一个 GPIO 控制 CH_PD** 实现，而非依赖 ESP 内部脚。
- 此差异对 OTA 逻辑**零影响**，仅工程接线不同。

---

## 4. 射频 / 覆盖风险（01S 临时方案的边界）

- 01S 板载天线抗扰一般，工业现场 / 远距离可能掉线。但 OTA.md §4 与易错 5 已设计「整包重下 + CRC + 回滚」，断网重连由 `网络离线态与分区设计.md` 的指数退避（10s→30s→60s）兜底，因此**偶发掉线不致命**。
- ⚠️ **但**：若现场持续弱信号，92 KB 包反复拉取会拉长升级窗口、增加 `boot_attempt` 误触发回滚的风险。建议：
  - **01S 仅用于实验室 / 原型验证**跑通链路；
  - **12F 到货后再上现场**（射频余量更足）。
- 不做断点续传（OTA.md 易错 5）：92 KB 在 115200 bps 约 6.6 s，**串口不是瓶颈**；真正耗时大户是 **Flash 擦除**（易错 12，单扇区最坏 2 s @x64）。

## 5. 迁移到 ESP-12F（到货后）

**H743 OTA 代码：零改动**（同一套状态机 / 校验 / 回滚）。只需：

1. **硬件**：换模组 + 接 12F 的复位 / 状态 GPIO（若采用）；**USART2 PA2/PA3 不变**。
2. **文档侧**（把 OTA.md 从 01S 对齐为 12F，本次不急，12F 到货再做）：
   - §0 命名统一段：`ESP-01S` → `ESP-12F（ESP8266EX）`；
   - §2 采购：`ESP-01S 已购` → 更新为 `ESP-12F 已到货`，旧 01S 留作备用 / 实验室机；
   - §5.7 接线：补充 12F 的 CH_PD / 复位脚、状态指示 GPIO 接法；
   - 射频描述按 12F 更新（PCB 天线、工业更稳）。
   - 可参考 `Doc/ESP12F/` 系列：`ESP12F_12S_裸模组_上电接线与烧录指南.md`、`ESP01S_固件选型_烧录与TLS可行性.md`、`ESP01S_MQTT_TLS_移植方案与RTOS落地.md`。
3. **验证**：同一份阿里云 OTA 包，先 01S 跑通，再 12F 复跑一次确认等价。

## 7. ESP-01S 能否完成 OTA 全链路？— 可行性判定

**结论：能完整完成。** 逐环节判定（每环节是否受 01S 限制阻断）：

| OTA 环节 | 01S 是否阻断 | 说明 |
|---|---|---|
| 阿里云订阅 / 拉取 URL | 否 | 同为 ESP8266EX，AT+MQTT 指令集一致（易错 1：已刷 MQTT 固件即可） |
| HTTP 分包拉取（USART2 115200） | 否 | 92 KB ≈ 6.6 s；串口非瓶颈（OTA.md §2） |
| 边收边烧进备用 Bank | 否 | 烧写在 H743 内部 Flash，与 ESP 无关；RWW 保证不 stall（OTA.md §3 / §5.3） |
| 整包 CRC32 校验 | 否 | BootLoader 重算，不依赖模组（易错 4 / 13） |
| 置 PENDING + 复位 | 否 | 写 S1 参数区，纯 H743 操作 |
| BootLoader 切槽 / 回滚 | 否 | 纯 Flash+CRC+跳转，无网络（OTA.md §4 / §5.2） |
| 新 APP 心跳固化 | 否 | 新 APP 经同 ESP 发 MQTT 心跳；01S 可发 |

**关键隔离性结论**：OTA.md §4 已定死「**BootLoader 不含网络，APP 才下载**」。因此 **ESP-01S 任何故障（掉线 / 死机 / 固件坏）都不会变砖 H743**——最坏只是旧 APP 继续跑、下次重下；回滚兜底由 H743 独立完成（§10 IWDG + `boot_attempt`）。这正是 01S 敢用来跑 OTA 的根本原因。

## 8. 可能出现的问题与解决（风险表）

| # | 风险 | 现象 | 根因 | 解决 | 关联 |
|---|---|---|---|---|---|
| 1 | AT 固件无 MQTT | 连不上阿里云，`AT+MQTTUSERCFG?` 无响应 | 出厂默认 AT 不含 MQTT | 刷带 MQTT 的 ESP-AT 固件（见 `Doc/ESP12F/ESP01S_固件选型_烧录与TLS可行性.md`），验证后再接 STM32 | 易错 1 |
| 2 | 下载中途掉线 | `ERR_NET`、CRC 失败、反复重下 | 01S 板载天线弱 / 现场信号差 | APP 内重试循环：保持 `FLAG=UPDATE`，**重擦 + 整包重下**（不做断点续传，OTA.md 易错 5）；进度走 MQTT 上报便于云端观察 | 易错 5 |
| 3 | TLS 握手慢 / 模组卡死 | HTTPS 拉包超时、ESP 无响应 | 01S CPU 较弱，TLS 握手慢 | ① 下载循环每 4 KB 喂 IWDG（§5.3 已做）；② **H743 控 CH_PD 硬复位 ESP 后重试**，不波及 H743；③ 超时阈值留足 | 易错 12 / §10 |
| 4 | 供电跌落 | ESP 随机重启、传输中断 | 与 MCU 共弱 LDO，峰值 300 mA 拉垮 VCC | **ESP 独立 3.3 V LDO + 储能电容**；OTA 前示波器确认 VCC 平稳 | §2 |
| 5 | USART2 接收丢字节 | CRC 偶发不匹配 | 中断 RX 缓冲不够 / 长帧溢出 | `HAL_UARTEx_ReceiveToIdle_IT` + 足够 ring buffer（≥ 最大 MQTT 帧）；丢字节由 CRC 兜底 → 重下 | §2 / 易错 4 |
| 6 | 烧写后回读 CRC 错 | 校验偶发失败 | D-Cache 命中旧行（OTA.md 易错 13） | 回读前 `SCB_InvalidateDCache_by_Addr()`（BootLoader 侧同样做） | 易错 13 |
| 7 | 发错槽镜像 | "OTA 成功却跑老版本" | 一份 bin 两槽通用（绝对地址） | 双 target（APP_SLOT1 / 2）；易错 11 自检拒收错位镜像 | 易错 10 / 11 |
| 8 | 回滚不触发 | 坏固件反复切槽、永不回滚 | 只在 CRC 失败计数，漏 `active==pending` 支 | BootLoader 在 `active_slot==pending_slot` 支单独 `boot_attempt++`（OTA.md §4 步骤 6） | 易错 6 |

> 以上 8 项中，仅 **#2/#3/#4** 与 01S 模组特性强相关（弱天线 / 弱 CPU / 供电）；#1 是 ESP8266EX 通用前置；#5–#8 与模组无关，是 H743 OTA 通用易错点。

## 9. ESP-01S 专项加固建议（弱天线 / 无 GPIO / 供电）

1. **信号门控（弱天线首要缓解）**：启动 OTA 前先查 Wi-Fi 信号质量（`AT+CWJAP?` / 信号强度），低于阈值则延迟 / 放弃本次升级，等信号好再触发——直接压低「风险 2」发生概率。
2. **独立供电**：ESP-01S 专享 3.3 V LDO（≥ 500 mA）+ 10~47 µF 储能电容，与 MCU 电源解耦，消除「风险 4」。
3. **CH_PD 受 H743 管控**：把 01S 的 CH_PD 接到 H743 一个 GPIO（而非直接上拉），模组卡死时 H743 拉低再拉高硬复位，无需人工断电——即「风险 3」的恢复手段，也是 01S 无多余 GPIO 时的"远程复位"实现（对应 §3）。
4. **状态指示走 H743**：01S 无暴露 GPIO，OTA 状态 / 进度用 H743 本地 LED + USART1 VOFA + MQTT 上报三重呈现（§3），不依赖模组灯。
5. **先用 01S 跑通实验室链路，现场等 12F**：01S 完成全链路验证即证明其 OTA 设计正确；12F 到货后换模组复验，射频余量更足、可上现场（§4 / §5）。
