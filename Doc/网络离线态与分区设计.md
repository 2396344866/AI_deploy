# 网络离线态与分区设计（联网功能二次开发参考）

> 配套 `待处理.md` §网络重构。本文件定义"离线态"行为边界与二次开发钩子，便于后续补全联网功能时直接对齐。

## 1. 决策来源（用户 2026-08-30 决议）
- **凭据**：外置到 `esp01s_config_local.h`（真实值，已 gitignore）；`esp01s.h` 经 `__has_include` 引入，缺失则回落占位。
- **重试**：指数退避 `10s→30s→60s`(封顶) + 连续失败阈值 → `NET_OFFLINE`。
- **离线**：跑"非联网部分"；网络每 60s 触发一次重连。

## 2. 状态机
```
NET_INIT → NET_CONNECTING → NET_ONLINE ⇄ NET_RETRYING → NET_OFFLINE
```
- 任何态每轮 `task_heartbeat_kick(HB_NETWORK)` —— OFFLINE **不会**饿死 IWDG。
- 状态切换打 `LOG_I("NET", "entering <state>")`，便于现场定位。

## 3. 离线分区（哪些跑 / 哪些挂起）
**本地照常（不依赖云）：**
- Logger（常驻抽空 + 控制台）
- 黑匣子 Flash 写入
- ESP32-S3 图像任务
- 九轴 IMU 本地姿态融合
- 显示屏
- 电机（若 `APP_ENABLE_MOTOR`）
- 故障诊断推理（仅用**本地**传感器）

**联网态才跑（离线挂起）：**
- MQTT 发布到云平台
- 依赖"云平台下发传感器数据供推理"的推理（**未来二次开发功能**，当前未实现，离线自然不跑）

## 4. 网络任务行为（StartNetworkTask 重构要点）
- `NET_INIT / CONNECTING / RETRYING`：到 `s_next_try` 才尝试连接；退避间隔 `min(10000 * 2^attempt, 60000)`；
  成功 → `NET_ONLINE` 并清失败计数；失败 → 计数++，达阈值(默认 6) → `NET_OFFLINE`（重连计时 60s），否则 `NET_RETRYING`。
- `NET_ONLINE`：数据就绪则发布（带超时）；发布失败 → 转 `NET_RETRYING`。
- `NET_OFFLINE`：仅每 60s 触发一次重连；成功 → `NET_ONLINE`。
- 发布缓冲：离线时最新一帧 JSON 暂存静态缓冲，重连后补传（**待二次开发完善**；当前仅 POST 单次结果，挂起不丢）。

## 5. 诊断接口
- 控制台 `n` 命令（`APP_ENABLE_NETWORK` 守卫）打印 `net_state` + 失败计数 + 下次重连剩余秒数。

## 6. 二次开发钩子（联网功能补全处）
1. `StartNetworkTask` 的 `NET_ONLINE` 分支：新增**周期采样 → 发布**（替换当前仅 POST 单次结果）。
2. 云端下发传感器数据 → 推理：在 Inference 任务加"云端模式"，离线回落本地传感器。
3. 缓冲落 Flash 环形：参考 logger 黑匣子 `s_crit_rb` 设计，做断网期发布队列持久化。
4. 凭据若需防固件提取：在"配置外置"之上叠加运行时解密（STM32 UID 派生密钥 + RDP2/OTP）。
